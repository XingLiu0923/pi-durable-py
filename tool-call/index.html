先认清五种记录

同一个会话里，请求的处理结果、消息内容和执行进度各有对应记录。记录通过 ID 或文档地址连起来。

Conversation
这段对话的归属范围。
其他记录用 conversation_id 指向它。
Submission
一次输入处理到哪了，回答在哪里。
entry 指向输入，answer 指向回答。
Entry
已经写下的一条消息。
用户问题、模型回复、工具结果。
Task
一项工作执行到哪一步。
state 保存状态和 checkpoint；结束后保存 outcome。
Document
会话的配置和可变状态。
kind 指明用途，key 指明属于谁。

pi.agent 保存模型与工具配置 · pi.live 保存当前 run 和进度 · pi.inbox 保存排队输入 · pi.usage 累计用量。

页面的 _live 是 Scheduler 在内存里的未结束任务索引，_docs 是 Document 缓存。它们根据存储记录建立；Invocation 保存一次调用的代码引用和异步执行信息。

发生了什么

  1. 把工具调用变成可以调度的任务

    模型先返回 tool_calls，同一次提交保存 assistant Entry #5、创建工具 Task #6，并把生成 Task #4 标为 waiting，等待 #6 进入终态。等待期间，#4 不需要占用一个一直运行的 Invocation。

  2. 先保存执行意图，再调工具

    工具 Task #6 在调用 get_weather 前，先提交 execute checkpoint，把参数和 replay 策略存起来。工具返回后，再提交 tool-result Entry #7，把 #6 标为终态并在 outcome 中记录 entry_id: 7。

  3. 依赖满足后继续生成

    Scheduler 重新调度 Task #4。#4 确认工具任务的 outcome 后，创建新的生成 Task #8，并让 pi.live.run.task_id 指向 #8。#8 会把工具结果放入模型上下文，继续回答同一个 Submission #2。
