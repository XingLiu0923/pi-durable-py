子 Agent 怎样接活并把结果传回来

主会话通过一个工具把工作交给子会话。两个会话各有自己的输入和回答，任务所有权把它们串在了一起。

先认清五种记录

同一个会话里，请求的处理结果、消息内容和执行进度各有对应记录。记录通过 ID 或文档地址连起来。

Conversation
这段对话的归属范围。
其他记录用 conversation_id 指向它。
Submission
一次输入处理到哪了，回答在哪里。
entry 指向输入，answer 指向回答。
Entry
已经写下的一条消息。
用户问题、模型回复、工具结果。
Task
一项工作执行到哪一步。
state 保存状态和 checkpoint；结束后保存 outcome。
Document
会话的配置和可变状态。
kind 指明用途，key 指明属于谁。

pi.agent 保存模型与工具配置 · pi.live 保存当前 run 和进度 · pi.inbox 保存排队输入 · pi.usage 累计用量。

页面的 _live 是 Scheduler 在内存里的未结束任务索引，_docs 是 Document 缓存。它们根据存储记录建立；Invocation 保存一次调用的代码引用和异步执行信息。

发生了什么

  1. 主会话启动工具，工具创建子会话

    第 5 次提交把主会话的 generation Task #4 改为 waiting，并创建工具 Task #6。第 8 次提交由 #6 创建子会话 #7，写入它自己的 pi.agent，并让 Conversation #7 的 owner 指向 Task #6。

  2. 子会话处理自己的 Submission

    第 9 次提交在子会话建立 Submission #8、用户 Entry #9 与 generation Task #10。第 12 次提交写入子回答 Entry #11，并把 #8 的 answer 设为 #11；此时 #11 仍属于子会话。

  3. 工具把子回答带回主会话

    第 13 次提交由 Task #6 在主会话写入工具结果 Entry #12。主会话随后开启 Task #13，使用这条工具结果生成最终回答，并在第 18 次提交结算主会话的 Submission #2。
