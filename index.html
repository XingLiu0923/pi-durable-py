用户问了一句，框架怎样把问题交给模型，再把回答交回来？沿着这一次请求，看看消息和执行状态分别存在哪里。

发生了什么

  1. 为会话保存配置

    先创建会话 #1，并同时保存它的 pi.agent 配置。c:1 表示这份配置属于会话 #1，里面指定用叫 fake 的模拟模型。

  2. 接收输入，再启动任务

    同一批写入会记录请求回执（Submission #2）、用户消息（Entry #3）和待执行的 Task #4。Scheduler 先把任务写成 running，再真正开始执行。

  3. 保存答案，结算 Submission

    模型给出回答后，框架保存回答，把 Submission #2 标成 done，并更新 Task 状态。之后，沿着回执的 entry 和 answer 两个字段，就能分别找到原问题和回答。

组件时序图

虚线是组件调用。指向 DB 的实线是一批存储写入，点开可按表查看字段变化和 SQLite 代码。

数据来自 Python 教学版的一次运行，使用模拟模型和 MemoryStorage。DB 表示存储层。组件调用由代码和写入顺序还原，运行状态只在提交发布时采样。

Scheduler 先预留任务，再启动 Invocation

_reserve() 内部等待提交成功才返回，_start() 再将 Invocation 放入内存索引。第 3 次提交发布时，可以在图里看到 running 的任务和空的 _invocations。
